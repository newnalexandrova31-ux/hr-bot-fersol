## Детальный анализ по файлам

### 1. `main.py`

#### ✅ Что хорошо
- Чёткое разделение handlers
- Fallback для Markdown-ошибок
- Логирование администратору

#### ⚠️ Проблемы

**P1 (Критично): Синхронный вызов LLM**
```python
# Строка 27 — блокирующий вызов
response = ask_gemini(user_query)
```
**Проблема:** `ask_gemini()` — синхронная функция. При 1000 пользователях это заблокирует event loop, и бот перестанет отвечать.

**Решение:**
```python
import asyncio
from concurrent.futures import ThreadPoolExecutor

executor = ThreadPoolExecutor(max_workers=10)

async def chat_handler(message: types.Message):
    loop = asyncio.get_event_loop()
    response = await loop.run_in_executor(executor, ask_gemini, user_query)
```

---

**P2 (Высокий): Нет rate limiting**

**Проблема:** Один пользователь может отправить 100 сообщений за минуту и исчерпать API-лимиты OpenRouter.

**Решение:** Добавить middleware с ограничением:
```python
from aiogram.dispatcher.middlewares import BaseMiddleware
from collections import defaultdict
import time

class RateLimitMiddleware(BaseMiddleware):
    def __init__(self, limit: int = 10, window: int = 60):
        self.limit = limit
        self.window = window
        self.users = defaultdict(list)
    
    async def __call__(self, handler, event, data):
        user_id = event.from_user.id
        now = time.time()
        self.users[user_id] = [t for t in self.users[user_id] if now - t < self.window]
        
        if len(self.users[user_id]) >= self.limit:
            await event.answer("⏳ Слишком много запросов. Подождите минуту.")
            return
        
        self.users[user_id].append(now)
        return await handler(event, data)
```

---

**P3 (Средний): Логи администратору могут не дойти**

**Проблема:** Если `ADMIN_ID` некорректный или бот заблокирован админом, ошибка логируется, но не отслеживается.

**Решение:** Добавить Sentry или файловое логирование как fallback.

### 2. `rag_engine.py`

#### ✅ Что хорошо
- Глобальный кэш экономит время
- Хорошо структурированный промпт
- Обработка исключений

#### ⚠️ Проблемы

**P1 (Критично): Кэш не инвалидируется**
```python
# Строки 36-43
_KNOWLEDGE_CACHE = None

def get_context():
    global _KNOWLEDGE_CACHE
    if _KNOWLEDGE_CACHE is None:
        _KNOWLEDGE_CACHE = load_all_knowledge()
    return _KNOWLEDGE_CACHE
```
**Проблема:** Если обновить `database.xlsx`, бот продолжит использовать старые данные до перезапуска.

**Решение 1 (Простое):** Добавить команду `/reload` для администратора:
```python
@dp.message(Command("reload"))
async def reload_handler(message: types.Message):
    if str(message.from_user.id) == config.ADMIN_ID:
        import rag_engine
        rag_engine._KNOWLEDGE_CACHE = None
        await message.answer("✅ База знаний перезагружена")
```

**Решение 2 (Продвинутое):** Следить за mtime файла:
```python
import os

_KNOWLEDGE_CACHE = None
_CACHE_MTIME = None

def get_context():
    global _KNOWLEDGE_CACHE, _CACHE_MTIME
    current_mtime = os.path.getmtime(config.DATABASE_PATH)
    
    if _KNOWLEDGE_CACHE is None or _CACHE_MTIME != current_mtime:
        _KNOWLEDGE_CACHE = load_all_knowledge()
        _CACHE_MTIME = current_mtime
    
    return _KNOWLEDGE_CACHE
```

---

**P2 (Высокий): Нет таймаута для API**

**Проблема:** Если OpenRouter завис, бот будет ждать вечно.

**Решение:**
```python
client = OpenAI(
    base_url="https://openrouter.ai/api/v1",
    api_key=config.OPENROUTER_API_KEY,
    timeout=30.0,  # Добавить таймаут
)
```

---

**P3 (Средний): Весь контекст в каждом запросе**

**Проблема:** При каждом вопросе отправляется ~60KB текста. При 1000 пользователях это:
- Высокие расходы на токены (если модель платная)
- Медленные ответы

**Решение:** Для production рекомендую вернуть векторный поиск:
- Использовать `faiss` или `chromadb`
- Отправлять только релевантные 3-5 фрагментов (~2-4KB)

```python
    sys.exit(1)
```

## Рекомендации для Production (1000 пользователей)

### 🔴 Критические (до запуска)

1. **Асинхронный вызов LLM** — без этого бот зависнет
2. **Rate limiting** — защита от спама и исчерпания лимитов API
3. **Валидация конфига** — понятные ошибки при старте
4. **Таймауты API** — защита от зависания

### 🟡 Важные (в первый месяц)

5. **Мониторинг** — Sentry или аналог для отслеживания ошибок
6. **Метрики** — счётчик запросов, времени ответа
7. **Логирование в файл/БД** — для анализа популярных вопросов
8. **Команда /reload** — обновление базы без рестарта

### 🟢 Желательные (оптимизация)

9. **Векторный поиск** — снижение расходов на токены
10. **Тесты** — unit и integration тесты
11. **CI/CD** — автоматический деплой при пуше в main
12. **Graceful shutdown** — корректное завершение при перезапуске

### 🔴 Высокий приоритет

**1. Кнопка «Связаться с HR»**

Если бот не может помочь → кнопка для связи с живым HR-специалистом.

*Почему важно:* Сотрудник не должен «застревать» в боте без выхода.

---

**2. Быстрые кнопки с популярными темами**

После `/start` показывать inline-кнопки:
```
[📅 Отпуск] [💰 Зарплата] [📄 Документы] [🏥 Больничный]
```

*Почему важно:* Снижает барьер входа, показывает возможности бота.

---

**3. Кнопки оценки ответа**

После каждого ответа:
```
[👍 Помогло] [👎 Не помогло]
```

*Почему важно:* Сбор обратной связи для улучшения базы знаний.

---

### 🟡 Средний приоритет

**4. Команда /help с навигацией**

`/help` → Список тем + примеры вопросов + как связаться с HR

---

**5. Сообщение при долгом ответе**

Если LLM думает > 5 сек → «⏳ Ищу информацию, подождите...»

---

**6. Структурированные ответы**

Вместо сплошного текста → эмодзи-маркеры, разбивка на абзацы
